# Plugin licensing and commercial activity

The authoritative terms are [LICENSE](../../LICENSE), [LICENSING.md](../../LICENSING.md#plugins-and-external-service-integrations) and the contribution-specific [CLA](../../CLA.md).

Meshable Ops uses a custom **source-available community license**, not AGPL or an OSI-approved open source license. Internal business use/modification is allowed. Commercial distribution/hosting of the application requires written permission from the creator or a rights-holder-authorized [Licensing Maintainer](../../MAINTAINERS.md).

## Paid plugins

Authors may sell copies, charge subscriptions, use paywalls and offer paid hosting/support/services for their separately identifiable plugins, retaining proceeds and ownership without automatic maintainer royalties. Covered extensions inherit the community license, including its paid-plugin exception and source/notice conditions. Required source accompanies paid copies at no extra charge; modified covered network versions offer source to their users at no extra charge.

The exception does not permit selling/hosting the application itself or repackaging the core as a plugin to evade restrictions. Independent plugin publication/sale is not CLA acceptance or a grant of commercial relicensing rights. Expressly contributing identified code under the CLA is a separate decision.

| Component | Treatment |
| --- | --- |
| App-derived React pages, Kotlin services, Python routes, and covered ZIP functionality | Community terms, paid-plugin exception, source and notice conditions. |
| Independently authored separable HTTP/protocol client | May retain a license permitting the actual combination; preserve upstream terms/notices. |
| Independent remote Git, chat, calendar or storage service | Its own license/service terms; API communication alone does not relicense it. |
| Core app renamed or moved behind a worker/API and sold as a plugin | Does not avoid the commercial application restriction. |

ZIP packaging, process boundaries, language and manifests alone do not determine independence. GPL/AGPL code cannot be assumed combinable with this custom restriction without adequate permissions. Identify upstream material, exact terms and rights holders and retain source/notices required for the actual release. A project commercial agreement cannot waive upstream rights.

Existing valid recipient licenses and earlier accepted agreements are not retroactively revoked. Contributors must expressly accept CLA 2.0 for identified new contributions; maintainers must retain the record. Obtain legal review before commercial release.
