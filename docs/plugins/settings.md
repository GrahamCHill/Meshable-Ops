# Plugin settings

Every installed plugin has a **Settings** entry in **Administration → Plugins**, including plugins without pages or connection credentials. Its menu contains **General** (activation, allowed roles, search, table policies), **Configuration** (plugin-specific fields), **Connections** (provided capabilities, required support, optional features), and **Data** when it owns tables. URLs retain the selected plugin/tab, for example `/admin/plugins?plugin=telegram&tab=configuration`.

Declare configuration fields in the backend manifest:

```kotlin
settingsFields = listOf(
    PluginSettingField("accountId", "Account ID", required = true),
    PluginSettingField("apiToken", "API token", PluginFieldType.SECRET,
        required = true, maxLength = 4096))
```

Include `PluginExtension.SETTINGS` for nonempty schemas. Override `WorkspacePlugin.validateConfiguration(values)` for provider-specific validation. This hook must be local validation only: saving settings must never contact a provider or send a message. The host rejects undeclared fields, control characters, overlong values, and stale revisions. A transaction-scoped per-plugin PostgreSQL lock also protects concurrent first saves across app instances. Declare `supportedRoles` to limit access choices; integration modules support `ADMIN` only. Custom modules can use the usual `ADMIN`/`USER` policies.

The host encrypts the **entire configuration JSON** in `workspace_plugin_configuration` using the existing AES-GCM wrapping key. `APP_SECRETS_ENCRYPTION_KEY` is required before any configuration can be saved. Retain the key separately from database backups. Startup migration rotates these records using the existing current/previous-key mechanism.

Configuration responses contain only declared non-secret values, the names of configured secret fields, missing required labels, and the revision. Secret values are write-only. A blank secret keeps the saved value; an explicit **Remove stored …** checkbox clears it. Removed schema fields are never exposed as public values. Drafts may omit required fields; operations remain unavailable until configured. Disabling retains configuration. Clearing a plugin's owned data retains this host-managed configuration.

Override `WorkspacePlugin.missingConfiguration(values)` for conditional requirements, such as Microsoft's own credentials versus an explicitly selected shared connection. It returns labels only and performs no network operations. Required capability checks are separate from configuration readiness; see [Composition](composition.md).

Server-side code can call `PluginConfigurationService.current(id)` to read credentials, after checking plugin availability and the actor's permissions. Never return or log that map. UI fields are generated by the host; custom plugin JavaScript is not required for settings.

| Endpoint | Purpose |
| --- | --- |
| `GET /api/admin/plugins/{id}/configuration` | Redacted configuration, revision, readiness; admin only, works while disabled |
| `PUT /api/admin/plugins/{id}/configuration` | `{ "values": { "accountId": "...", "apiToken": "replacement" }, "clearSecrets": [], "revision": -1 }`; admin only |

The PUT is a partial update: omitted fields remain; blank non-secret values clear them. Use the revision returned by GET (`-1` before the first save). On `409`, reload and reapply edits. Credentials are not included in the public plugin catalogue, metadata export, or search.
